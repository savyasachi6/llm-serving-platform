# 🎨 AI Micro-Agent Playground UI

The **Playground UI** is a responsive, modern React + TypeScript dashboard built with Vite and vanilla CSS glassmorphism styling. It serves as the interactive control plane for the **Cost-Efficient LLM Serving Platform**, allowing developers and users to submit customer support tickets and observe the real-time execution of the multi-agent assembly line.

---

## 🚀 Key Features

1. **Ticket Input Simulation**:
   - Pre-populated with realistic enterprise support queries containing simulated PII (SSNs, emails, credit cards, billing issues).
2. **Dynamic Triage Tagging**:
   - Color-coded badges for intent classification: `Billing` (red), `Technical` (blue), and `General` (green).
3. **PII Masking Audit Display**:
   - Monospace code panel displaying the sanitized ticket after the `RedactAgent` processes it, guaranteeing zero raw PII is passed to downstream generation models.
4. **Final Response Synthesis**:
   - Empathetic, factual response generated by `RespondAgent` utilizing prefix-cached knowledge base context.

---

## ⚙️ Architecture & Data Flow

```
[Browser / User]
       │
       ▼ (HTTP POST /api/process_ticket)
[Agent Worker (Port 8001)]
       ├── (Parallel) ──► [TriageAgent (Qwen 0.5B + reasoning-lora)]
       ├── (Parallel) ──► [RedactAgent (Qwen 0.5B + reflection-lora)]
       │
       ▼ (Strict Redaction Verification)
       └── (Sequential) ─► [RespondAgent (Qwen 1.5B Synthesis)]
```

## 💻 Local Development

### Prerequisites
- Node.js 18+
- npm or pnpm

### Quick Start
```bash
# Navigate to the playground directory
cd apps/playground

# Install dependencies
npm install

# Start the Vite development server with Hot Module Replacement (HMR)
npm run dev
```

The development server starts at `http://localhost:5173` (or `http://localhost:3000` depending on port availability).

### Production Build
```bash
# Compile TypeScript and bundle assets
npm run build

# Preview the production build locally
npm run preview
```

---

## 🐳 Containerization & Production Deployment

The playground uses a **multi-stage Dockerfile**:
1. **Stage 1 (Build)**: Node.js alpine image compiles TypeScript and outputs optimized static bundles to `/app/dist`.
2. **Stage 2 (Runtime)**: Lightweight Nginx alpine server serves the assets on port 80 with gzip compression and cache-control headers.

```bash
# Build the container image
docker build -t playground:v1.1 -f apps/playground/Dockerfile apps/playground

# Run locally mapping container port 80 to host port 3000
docker run -d -p 3000:80 --name llm-playground playground:v1.1
```
