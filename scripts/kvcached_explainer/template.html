Section 4 — How It Works

Think of It Like OS Virtual Memory — for GPU

Your vLLM engine still "sees" a huge contiguous KV address space. Physical GPU RAM is only wired in as tokens generate, then returned to a shared pool when a sequence ends.

📥

Request Arrives

kvcached maps physical GPU pages to the engine's virtual KV addresses on demand. No kernel rewrites needed.

⇄
CUDA VMM
page mapping
⚡

Tokens Generate

Attention kernels write KV tensors normally. Physical pages back them elastically as context grows.

♻
Pages
returned
🔄

Sequence Finishes

Physical pages unmapped and returned to the shared pool instantly. The other engine claims them immediately.

ℹ️
What kvcached does NOT touch: model weight memory, LoRA adapter swapping time, attention compute complexity, or your gateway/routing code.
